# 本機黑白名單

2026-10-20 更新。使用者指定兩種黑名單與白名單 ID 改色；此契約取代先前「第二級移除行」的規劃。只改本機呈現，不修改站端名單或文章。

## 三種策略

| 策略 | 文章列表 | 標準推文 |
| --- | --- | --- |
| 遮內容、保留 ID（mask） | 遮住標題欄（第 31–80 欄，含文章類型記號），保留編號、日期、作者 | 遮住冒號後至時間前的內容（含範圍內 IP），保留類型、ID、時間 |
| 整行塗黑（mask_row） | 命中作者的完整 80 欄塗黑 | 命中作者的完整 80 欄塗黑，包括 ID、時間 |
| 白名單（allow） | 只有作者 ID 改為亮青色 | 只有推文 ID 改為亮青色 |

三種策略皆保留行高、行數及站端座標。連續同 ID 的推文另依下節合併，後續行 ID 塗黑優先於保留 ID／白名單標色。白名單不改標題、推文或 ID 旁的留白；保留原本有效背景。沒有刪行、折疊、標題關鍵字、內文關鍵字、暱稱或提及字串比對。使用者仍能打開被遮黑的文章；文章正文不因作者而整篇隱藏。

## 辨識與共同輸出

[navigation](../src/navigation.rs) 先驗證完整 80×24 畫面、文章列表標頭／操作列／游標與每筆文章結構；[filters](../src/filters.rs) 只從已確認項目的作者欄（第 18–30 欄）取得完整 ID，刪除列的 `-` 不視為帳號。畫面導航沿用原始 Frame 的辨識，所以整行塗黑不會使目前列表失去鍵盤或滑鼠導覽。

正常閱讀頁的推文辨識沿用標準樣式：完整映射／ANSI、左端推／噓／箭頭與配色、完整作者與冒號樣式、右側固定月日時間及尾端留白。普通內文、截斷 ID、無作者續行、未映射與未完成畫面保留原樣，不從前一行或前一頁繼承作者。完全仿造格式與配色的內文仍可能誤判，這是畫面辨識的邊界。其他 BBS、信件／精華列表與未知版型不套用。

Rust 建立單一呈現 Frame：被遮 cell 替換為黑底黑字的 `█`，保留完整字形邊界，來源 Frame 留在 Rust 記憶體且不刪改。WebView、網頁文章快取、選取／複製、完整與選取行 PNG、網址／圖片候選皆使用這份投影；遮蔽內容與 OSC 8 目的地不能從其他出口恢復。PNG 使用同一 renderer，白名單 ID 顏色亦包含在 PNG；hover、選取與游標裝飾不包含在 PNG。

「暫時顯示遮蔽內容」只揭露當前 session／來源 revision 的黑名單內容，白名單 ID 標色仍保留。新畫面重設揭露。規則／揭露變更遞增獨立 presentation 版本、清除舊選取與媒體並重建文章快取；舊 PNG、複製、hover 或非同步結果均須通過版本檢查。設定與揭露不送 PTT bytes。

## 連續推文 ID 合併

預設自動將相鄰、已完整辨識且 ID 忽略 ASCII 大小寫相同的推文視為同組。第一行 ID 保留原色（白名單為亮青色），後續行只有 ID 字母範圍塗黑；推／噓／箭頭與冒號、正文、時間不受影響，切換推噓類型仍可接續。不同 ID、空行、截斷／無作者／未知格式皆中斷，不從提及文字推測作者。

網頁文章快取保留每行已辨識 ID 的 Rust metadata，已讀取的相鄰頁可合併；缺頁或新文章清理後重新起組。快取保留套用名單但尚未合併的行，避免移除舊行後新首行的 ID 永久消失。metadata 不傳給 WebView。終端機與單頁 PNG 各自保留該頁第一筆 ID；從網頁歷史選取／複製／行 PNG 則與目前可見快取投影一致。

合併在黑白名單後套用，暫時揭露黑名單不關閉合併。重複 ID 使用黑色 `█`，複製與 PNG 也保留遮罩；該範圍的 OSC 8 連結一併移除，正文連結不受影響。文章列表不合併，不改站端 Frame、行數或送鍵。

## 編輯與保存

預設空名單；最多 512 個完整 ASCII ID（1–12 字，英文字母開頭，其餘英數或底線），忽略 ASCII 大小寫。同 ID 手動編輯取代原策略／備註／拼寫；備註最多 128 字且不能有控制字元。白名單不是只顯示白名單帳號。

獨立 `filters.json` 保存於 OS 使用者設定目錄，上限 256 KiB，schema version 3。v1 的舊規則仍為 mask，v2 的 mask／allow 保留分類；只在記憶體遷移，明確儲存才寫新版。v1／v2 不接受 mask_row。保存使用同目錄暫存與原子替換，先將原 bytes 備份至 `filters.json.bak`；成功後才生效。讀取錯誤不覆寫原檔，保存失敗保留原生效規則，關閉表單丟棄未保存欄位。名單不進顯示 profile、不預設讀取其他程式私人檔案、不進產品 repo。

## PTTStar 參考與匯入

PTTStar Analyzer 的 3.9.4 靜態研究證實：完整 ID 忽略 ASCII 大小寫；B／C／W 分類與 ID 樣式分支存在。原版 B／C 遮蔽強度另由全域設定控制，推文選項含「整行移除」；不能把它等同本產品保留行列的塗黑。原版同 ID 後讀取覆寫；本產品沿用既有「匯入白名單優先」契約。研究不是原版動態或本產品實站驗收，原始研究留 repo 外。

選擇 UTF-8（可有 BOM）逐行文字，先預覽、再明確「合併並儲存」：

- `ID`、`ID=B:備註` → 遮內容、保留 ID。
- `ID=C:備註` → 整行塗黑，預覽明示這是本產品對應，計入調整數。
- `ID=W:備註` → ID 亮青色。

第一個冒號後保留備註；沒有冒號的 value 視為一般黑名單備註。等號分隔略過空欄、取前兩個非空欄。分類小寫、底線與 1–9 旗標僅保留分類並提示調整，不套外部顏色。N、混合分類、未知分類與非法 ID／備註計為略過，沒有可匯入項目則拒絕。白名單優先於兩種黑名單，不依重複行順序改變；其他未衝突既有項目保留。

Files 背景工作槽擁有讀取／解析／保存；確認時重查 request 與原規則快照。取消、關閉或晚到結果不套用。保留匯入來源與本機備份。`account_lists`／`account_articles` 探針使用自製資料與獨立目錄，不能代替系統選檔、原生正文滑鼠或實站驗收。

## 驗證

本次驗證結果維護於 [active plan](active/minimal-browser.md)。核心須涵蓋三策略、文章／推文範圍、ID 對比、舊檔升級、白名單衝突、完整行列與輸出一致性；另驗 store、presentation、文章快取與原生 Dioxus 像素／複製／PNG。未執行的平台或案例不記為通過。

## 先前一般推文遮黑的驗證（2026-10-16）

5 個核心案例驗證標準推文範圍、完整 ID／大小寫／容量、原始 Frame 保留、所有輸出使用同一投影、未知／截斷／引用反例，以及規則／揭露版本失效。desktop 的 2 個 store 案例覆蓋保存、備份、損壞／超量與寫入失敗；bin 的共用 admission 案例確認舊規則、揭露、session 或來源 revision 的消費者均拒絕。

macOS arm64／WKWebView 原生表單驗證新增、大小寫更新同 ID、備註、移除、非法 ID 拒絕、備份路徑受阻時保留規則、關閉丟棄草稿與再次選取既有項目。正常保存後第二個程序載入同一檔案，畫面與先前遮黑 PNG 逐像素一致。系統剪貼簿讀回確認命中行為方塊；整頁讀回亦觀察到兩則命中範圍的遮罩（原生 AX 長文字讀回會截短，其他範圍由核心獨立 expected 驗證）。

獨立 Pillow 解碼 PNG：960×576，僅兩則命中推文的內容 cell 改變，其餘像素差異為 0；遮罩區全為黑色 RGB，揭露後與原圖相同；單行 960×24 與整頁對應裁切完全一致，整頁行範圍匯出亦相同。暫時顯示後換頁往返恢復遮黑，舊選取失效。最終過濾 probe 的四次保存、三次揭露操作與複製／兩種 PNG 均通過，peer 僅接受兩筆翻頁與 Close，⌘Q 後 ACK／worker join／listener released。相同 executable 的既有 34 筆 Vim 回歸與 ⌘W 亦通過。

首次表單流程發現 macOS Edit 選單缺少全選，已另修正並以 ⌘A 取代 ID／備註驗證；一次中途雙擊揭露網址超出 filter probe 的範圍而中止，不算完整通過。後續流程完成上述驗證。部分後續座標滑鼠操作曾受 CUA noWindowsAvailable 限制，使用原生工具列完成全頁選取；單行滑鼠選取的 PNG 與剪貼簿另有前一候選包的已完成子案例。

另在正常 App 使用專用測試帳號，實站 SYSOP 公開置底公告的同帳號兩則標準推文可遮黑，保留作者／時間；揭露還原、Ctrl+b／Ctrl+f 往返後重新遮黑，Vim NORMAL。測後由表單移除暫時規則，並只清除本次新建的空名單及測試備份以還原原先不存在的狀態；⌘Q 回報 PeerClosedWithoutReply，程序退出 0。沒有保存實站畫面、文章內容、流量、帳密或私人名單進產品及驗證資料。

一般 core／Clippy、38 個 desktop lib、2 個 bin 與文件 gate 通過；完整 macOS desktop gate 仍為 not_ready，Windows／Linux、其他格式與真實網站 hover 不在本輪通過範圍。
