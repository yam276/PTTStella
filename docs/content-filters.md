# 本機名單與內容過濾方案

2026-10-16。狀態：**第一級已實作並完成有限 macOS 驗證；第二級仍為設計**。範圍為瀏覽期間的帳號名單、文章標題條件及備註，不操作站端的使用者名單或文章資料。

## 使用者確定的兩級方向

- 一般黑名單：將命中的推文內容遮黑，保留原來位置。
- 封鎖名單：命中的推文直接從本機閱讀呈現消失，後續內容補上。

2026-10-16 先前暫緩名單；後續使用者已授權實作一般黑名單的最小版本，目標見 active plan。第二級需要先決定跨頁推文、行數與捲動、來源到畫面座標、選取／複製／截圖及暫時揭露的共同模型；不能直接刪除 Screen 的格線，或只以 CSS 隱藏一行。以下固定格線遮罩僅是第一級的可行方向；第二級仍待研究與確認。白名單的例外作用與兩級優先序也留待同時決定。

## 待細化的規則

帳號可有「一般黑名單／封鎖名單／例外／一般備註」策略，保存 ID、作用範圍與選用備註。精確比較完整 ASCII ID，忽略英文字母大小寫，保留原始顯示拼寫；不拿相似 ID、暱稱、推文中的提及或內文子字串代替作者身分。

標題規則先支援非空的字面包含條件，明確表示英文字母大小寫是否忽略；不加入 regex、腳本、拼音或模糊比對。預設只作用文章標題；推文內容關鍵字是額外作用範圍，不由一個模糊開關隱含擴散。

建議優先序：先看帳號策略；封鎖則套用該 scope 的隱藏，例外則略過該帳號在該 scope 的關鍵字隱藏；其餘再比對字面條件。一般備註不改過濾結果。同一 ID 不能同時有封鎖及例外；編輯時明確取代，不依檔案順序決定。這是本產品自己的策略，須以獨立 expected 固定，不能假定其他客戶端有相同優先序。

兩級名單使用明確文字分類，不加入複雜旗色組合。需要標記時只加小型低干擾記號或細底線，備註另顯示；維持 PTT ANSI 文字對比，不重畫發光整列。名單介面不用 Tab 或目前的 Vim 導覽鍵強行取代站端功能。

## 固定格線的隱藏方式

一般黑名單的遮罩方向保留 80×24 cell 與原始行列座標，對已確認的標題／推文範圍套用本機遮罩，提供「已隱藏／暫時顯示」入口及命中原因。核心 Screen 不刪 bytes 或刪行；封鎖名單需要另行設計可追溯來源的閱讀呈現層。任何未知、未映射或不完整語意範圍都不過濾。

白名單在這裡是「明確例外」，不代表只顯示名單內帳號。封鎖一個帳號也不等於網路層封鎖：PTT 畫面仍已收到，原 Frame 保留於記憶體。暫時顯示是本機動作，不送站端；新 session 或切換畫面時依有界的顯示狀態重置。

隱藏區的網址不提供 hover 載入／點擊開啟，選取／複製與 PNG 必須使用同一份過濾呈現結果，避免文字看不到卻從匯出漏出。預設複製與截圖保留遮罩及行寬；使用者明確選擇暫時顯示後才包含原內容。不能只在 Canvas 上蓋一層，同時讓剪貼簿仍抽出原始 Frame。

滑鼠座標和 Vim 操作繼續對應站端項目，不因遮罩自行跳過、刪除或改寫文章。遮罩列仍可明確操作站端選取／開啟；「隱藏」與「禁止開啟文章」不是同一個設定。

## 語意與資源所有權

[navigation](../src/navigation.rs) 目前只有可見項目、游標及少數閱讀狀態，尚無完整作者／推文模型。第一級已由 filters 在 Rust 的單一邊界產生符合標準格式的推文 ID 與 cell 範圍，再由名單引擎產生結構化呈現決策；標題與更多推文格式仍是後續範圍；UI、網址、選取與 PNG 共用此結果，不各自重新解析 ANSI、Big5 或文章文字。

跨行推文、截斷 ID、引用推文、暱稱及非標準 footer 須有負面案例。看起來像 `推 ID:` 的文章內文不能單憑字串外觀當成推文作者。站端沒有語意協定，辨識仍有明確 heuristic 邊界，不能宣稱抵抗刻意仿造整頁內容。

呈現結果的身分須包含 session／Frame revision、規則版本及暫時顯示版本。規則或揭露狀態改變時，即使站端 Frame 沒更新，也要使舊選取快取、PNG request 與 hover 授權失效，先重新取得同一呈現結果再輸出；不能只用原本 Screen revision 放行舊的未遮罩資料。

規則由單一 Rust store 管理、有版本與容量限制；載入／保存失敗保留原檔，明確編輯才寫入並保留備份。規則採結構化欄位，不把分類、顏色、底線與備註塞在一個冒號字串。初期使用資料預算與規則／文字長度驗證約束 CPU、記憶體及輸出，不使用無界 regex 或每次 draw 重新編譯條件。

私人名單另外匯出／匯入，與 [顯示 profile](preferences-and-profiles.md) 分開，只有使用者明確選擇才包含名單。第一版不自動讀取其他程式的個人檔案，也不預設加入任何封鎖帳號。研究資料與個人名單不進產品提交。

## 分段與驗收

1. 先擴充內容辨識及共用呈現結果，驗證已識別／未知範圍、完整 ID、標題與推文的獨立 expected。
2. 再做名單 CRUD、備註、優先序、保存與錯誤回復，先只套用已識別的一般列表與推文；其他畫面維持原樣。
3. 接遮罩／暫時顯示、連結／hover 排除、選取／複製及 PNG；以真正 Dioxus 像素及系統剪貼簿確認隱藏結果一致。

必要反例包括 ID 前後綴、不同大小寫、同 ID 重複規則、例外與關鍵字衝突、空條件、未映射字、半個 ANSI frame、切頁／重連及晚到圖片。套用、暫時顯示與設定匯入都不能送 PTT bytes、改動核心來源，或污染下一個 session。

前期研究已取得 repo 外的原生靜態 Evidence；該階段未執行目標操作或新產品過濾功能。分類／標記、完整 ID 與標題包含匹配有來源路徑支持；完整舊格式遷移與所有隱藏級別的動態行為仍未建立。以上產品優先序、遮罩及匯出規則是設計決定。

## 第一級實作契約

本輪僅提供一般黑名單推文遮黑。空名單為預設，最多 512 個完整 ASCII ID（1–12 字、英文字母開頭，其餘為英數或底線），忽略英文字母大小寫；同 ID 的更新明確取代原備註與顯示拼寫。備註最多 128 字且不含控制字元。沒有白名單、關鍵字、文章列表隱藏、刪除推文、舊格式匯入或其他程式的設定讀取。

Rust 在已辨識的正常 80×24 閱讀頁，檢查完整映射／ANSI、左端推／噓／箭頭與原色、完整作者及冒號樣式、右側固定月日時間欄與尾端留白。格式參考公開站端的 [FormatCommentString](https://github.com/ptt/pttbbs/blob/908bb0631a4a6db41eac85713637adf1a6058fde/mbbsd/comments.c#L4)，產品實作使用自己的 Frame 與自製資料。普通內文、引用、暱稱、截斷、無作者續行、非標準／舊推文格式與未完成畫面保留原樣；沒有跨頁繼承作者。完整仿造格式與配色的文章內容仍可能誤判，這是畫面辨識的邊界。

命中後只遮住冒號後至時間前的範圍（含該範圍內的 IP），保留推文類型、作者、時間及原行列。呈現 Frame 把被遮 cell 換成黑色方塊，選取／複製得到同欄數的 `█`，PNG 使用同一 renderer；原始 Frame 不刪改，也不把被遮原文送給 WebView。網址與圖片候選只從呈現 Frame 產生。

工具列顯示遮黑則數與 ID 原因，提供本畫面的「暫時顯示推文／恢復遮黑」。揭露只屬於當前 session／來源 revision，更新畫面即重設，不保存到磁碟。規則／揭露另有單調 presentation 版本，所有選取、PNG、連結及 hover 都須通過來源與 presentation 核對；變更同時清除選取與媒體，舊非同步結果不能恢復授權。

獨立 `filters.json` 保存於應用程式的使用者設定目錄，schema version 1，上限 256 KiB；不進顯示設定檔。新增／更新或移除並儲存才寫入，成功後才套用；關閉表單丟棄未儲存欄位。寫入使用同目錄暫存與替換，保存前備份原始 bytes 至 `filters.json.bak`。讀取／保存錯誤明確顯示，原檔與已生效規則保留；損壞檔不自動覆寫，使用者明確儲存可備份後修復。

## 本輪驗證範圍

5 個核心案例驗證標準推文範圍、完整 ID／大小寫／容量、原始 Frame 保留、所有輸出使用同一投影、未知／截斷／引用反例，以及規則／揭露版本失效。desktop 的 2 個 store 案例覆蓋保存、備份、損壞／超量與寫入失敗；bin 的共用 admission 案例確認舊規則、揭露、session 或來源 revision 的消費者均拒絕。

macOS arm64／WKWebView 原生表單驗證新增、大小寫更新同 ID、備註、移除、非法 ID 拒絕、備份路徑受阻時保留規則、關閉丟棄草稿與再次選取既有項目。正常保存後第二個程序載入同一檔案，畫面與先前遮黑 PNG 逐像素一致。系統剪貼簿讀回確認命中行為方塊；整頁讀回亦觀察到兩則命中範圍的遮罩（原生 AX 長文字讀回會截短，其他範圍由核心獨立 expected 驗證）。

獨立 Pillow 解碼 PNG：960×576，僅兩則命中推文的內容 cell 改變，其餘像素差異為 0；遮罩區全為黑色 RGB，揭露後與原圖相同；單行 960×24 與整頁對應裁切完全一致，整頁行範圍匯出亦相同。暫時顯示後換頁往返恢復遮黑，舊選取失效。最終過濾 probe 的四次保存、三次揭露操作與複製／兩種 PNG 均通過，peer 僅接受兩筆翻頁與 Close，⌘Q 後 ACK／worker join／listener released。相同 executable 的既有 34 筆 Vim 回歸與 ⌘W 亦通過。

首次表單流程發現 macOS Edit 選單缺少全選，已另修正並以 ⌘A 取代 ID／備註驗證；一次中途雙擊揭露網址超出 filter probe 的範圍而中止，不算完整通過。後續流程完成上述驗證。部分後續座標滑鼠操作曾受 CUA noWindowsAvailable 限制，使用原生工具列完成全頁選取；單行滑鼠選取的 PNG 與剪貼簿另有前一候選包的已完成子案例。

另在正常 App 使用專用測試帳號，實站 SYSOP 公開置底公告的同帳號兩則標準推文可遮黑，保留作者／時間；揭露還原、Ctrl+b／Ctrl+f 往返後重新遮黑，Vim NORMAL。測後由表單移除暫時規則，並只清除本次新建的空名單及測試備份以還原原先不存在的狀態；⌘Q 回報 PeerClosedWithoutReply，程序退出 0。沒有保存實站畫面、文章內容、流量、帳密或私人名單進產品及驗證資料。

一般 core／Clippy、38 個 desktop lib、2 個 bin 與文件 gate 通過；完整 macOS desktop gate 仍為 not_ready，Windows／Linux、其他格式與真實網站 hover 不在本輪通過範圍。
