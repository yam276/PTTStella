# 閒置保活

每次啟動預設開啟。上緣 hover 工具列的「防閒置：開／關」可暫停本次啟動的保活；同一視窗重連保留開關，重新啟動恢復預設開啟。此開關不修改顯示設定檔，不自動登入、不預防 OS 休眠。

## 送出內容與來源

在允許的畫面閒置 60 秒後，一次送出兩個 Ctrl+L（`0c 0c`）。選用刷新，不送方向鍵、Enter 或文字，不主動改變文章位置。

依 [ptt/pttbbs 輸入 hook](https://github.com/ptt/pttbbs/blob/90f07d655b8d7e85298ef26bdb63f40646fd9d17/mbbsd/io.c#L273)（核對於 2026-10-16，commit `90f07d655b8d7e85298ef26bdb63f40646fd9d17`），Ctrl+L 會重繪並在系統 hook 被消化，不交給畫面命令。活動時間更新另檢查兩次輸入的間隔；連續送出兩個 Ctrl+L 對應此條件。這是公開來源的推論，沒有證明目前實站部署版本或實測閒置登出效果。產品未搬入站端程式。

WebSocket Ping／Pong 仍由傳輸處理，與此 BBS 刷新路徑分開；不把成功寫入等同站端已接受或成功保活。

## 允許條件與暫停

- Connection 必須已連線，當前 Screen 可依 [導覽契約](navigation.md) 辨識為文章列表或一般閱讀頁。
- UI 必須對相同 generation、revision、input epoch 回報可用。組字、貼上、多行預覽、字型 dialog、拖曳、文字選取、匯出、導覽或等待畫面更新時不回報可用。
- 登入、密碼、編輯、確認或其他未辨識畫面不保活。畫面分類是保守 heuristic，不是站端提供的已登入／操作狀態協定，也不宣稱能識別所有自訂畫面。
- 輸入、操作暫停／恢復、畫面版本變更、重連或計時中斷後重新等待閒置期限，不補送錯過的次數。

Connection 擁有唯一單調時鐘與送出序列。一般週期每秒檢查一次，使用 Skip 策略；觀察到超過五秒的計時缺口便撤銷 UI 許可並重計期限。UI 暫停透過可合併的 watch 狀態回報，不會因輸入佇列滿而丟失。最後送出前再核對當前畫面及許可，手動操作優先於計時分支。

自動刷新等待五秒仍沒有新畫面版本時，僅釋放該自動操作的等待、關閉保活並顯示原因，手動鍵盤／滑鼠仍可使用；不把較新的手動輸入一併清掉。傳輸送出失敗沿用實際錯誤與斷線流程，不自動重送。收到新終端 bytes 不等於特定操作的協定確認。

## 驗證邊界

一般測試僅使用自製畫面與 loopback，不連實站。單調時鐘案例核對預設 60 秒、許可版本、暫停與計時缺口；production Connection 的短期限案例使用相同 timer／送出路徑，核對精確 `0c 0c`、待更新不重複、關閉、過期 session／畫面、未知提示、輸入競態、無回應恢復，以及不清除較新手動等待。

Windows WebView 以 trusted 輸入核對預設開啟、切換、選字／組字／dialog／未知畫面的 owner 暫停與恢復，並執行既有畫面、PNG、導覽及清理 gate。未完成實站長時間登入後驗收、實體 IME／睡眠恢復、macOS 或 Linux 驗證；不宣稱所有 timeout 或站端斷線均可避免。

主視窗內的設定對話框開啟時，Rust 立即撤銷 Connection 的保活 gate，並同步主 WebView 的 settings visibility；後續 gate 也必須核對該狀態。對話框關閉後，由原本畫面／輸入版本重新判定是否恢復，設定視窗不建立第二個 timer。
