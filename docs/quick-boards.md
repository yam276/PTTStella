# 有界快速切板

本契約對應使用者授權的快速切板與本機最近清單。Rust 單一流程、快速切板 UI 與最近清單已實作；平台及實站驗收進度見 [active plan](active/minimal-browser.md)。

## 板名與辨識

板名採 2–12 個 ASCII 字元，英文開頭，其餘英數或 `_-.`，外圍空白可清除，站端比對忽略大小寫，確認後保存畫面中的正式名稱。規則依公開 [板名驗證](https://github.com/ptt/pttbbs/blob/68b88d8753d6/common/bbs/string.c#L21) 與 [IDLEN](https://github.com/ptt/pttbbs/blob/68b88d8753d6/include/pttstruct.h#L13)，不把任意文字直接送成按鍵。

畫面仍由 Rust navigation 分析。板名從已辨識文章／空文章列表的頂列末端 `看板《名稱》` 取得；保留既有合成舊格式的 `看板: 名稱 人氣:數字`。先取實際末端欄位，不從中文敘述內的同名文字猜測。板列表則核對游標所在列的固定名稱欄，分類與目錄不當成已選看板。

## 單一送出與等待

Connection 持有唯一工作，UI 不持有鍵串、站端狀態機或 timer。每次開始核對 generation、revision、input epoch、沒有其他登入／切板或待回應輸入，以及已辨識來源畫面。要求與取消以最初的 operation Stamp 對應，舊取消不能停止後來的工作。

1. 主選單僅在看見已辨識的 Favorite 項目時送 `f`，等看板列表。閱讀頁先送返回、等文章列表，再返回；文章列表從返回開始。空板列表可直接搜尋。
2. 在確認的板列表送 `s`，等待頂列反色「搜尋全站看板」、第二列精確空白輸入提示與對應游標；已輸入、未完成 ANSI 或同步輸出都不送板名。
3. 只在該提示送板名與 CR 一次。依 [站端全站搜尋](https://github.com/ptt/pttbbs/blob/68b88d8753d6/mbbsd/board.c#L2170)，目標若已在目前列表，可能只移動游標；確認該列名稱吻合後，才送方向右進板。不在列表時可能直接進文章列表，因此也接受已確認的直接到達。
4. 只有目標板的完整、已辨識文章／空文章列表才報告 Reached，使用正式名稱。已經在目標板時不用發鍵。操作啟動的 Reply 只確認工作開始，不能當成已到達。

每步最長 5 秒、整體最多 30 秒，不因片段或錯誤畫面重設期限，不重送同一步。未收到預期畫面會停止；進板圖、說明頁與登入提示立即交還手動，不自動按任意鍵或回答確認。取消、有效的手動輸入／導覽、斷線與新 session 停止後續步驟；已送 bytes 不能撤回，重連不恢復。

新步驟前先讓已排入的手動操作及 UI 准入更新執行。唯一 write_input 在 await 傳輸前更新 input epoch 與等待狀態，撤銷直接讀 watch 的舊匯出／hover lease；切板期間暫停保活，不增加另一個送鍵 task。清理仍由原 Connection／UI owner 負責。

## 本機視窗

工具列或 ⌘K／Ctrl+K 開啟草稿視窗；這組快捷鍵保留給客戶端，不送 PTT。輸入或組字本身不送站端，按「前往」或非組字中的 Enter 才要求 Rust 啟動。保留超過 12 字元的草稿讓 Rust 拒絕，不將貼上內容截成另一個有效板名。來源未知或待回應時明確拒絕，錯誤保留草稿。

Esc／取消清空草稿，未確認前零站端輸入；已要求開始則取消尚未完成的步驟。工具列「停止切板」對應該工作的原始 operation，不以現在游標位置猜取消對象。UI 有自己的 request ID，取消／重新開啟後的舊回覆不會關閉新草稿，session 改變會釋放等待。清理時先撤銷事件與工作，再由同一 renderer、Connection 與 file owner join。

IME 的 composition、isComposing 與 legacy 229 都不兼任送出；下一個普通 Enter 可明確確認。JS doubles 覆蓋此界線，不冒充原生候選窗驗收。

## 最近看板

最近清單最多 20 筆，以已辨識文章／空文章列表的正式板名去重，忽略大小寫並將最近確認的名稱放在最前。選中的板列表列、搜尋草稿、進板圖、同步中的舊圖或尚在等待輸入回應，都不會當成到達。從手動操作進入已辨識板頁也可記錄。清除後停留原畫面不會立刻重新加入；再次離開並進入才視為新到訪。

點清單項目只填入草稿，不發送站端 bytes，仍須明確按「前往」。清單與存檔訊息位於切板視窗，不將保存失敗當成切板失敗。提供清除按鈕；沒有資料時仍可用，以便明確恢復無法載入的檔案。

Files 在 blocking worker 載入及保存獨立的 OS local-data `recent-boards.json`，version 1，只含板名、上限 4 KiB；不含帳號、文章或 session bytes，不放入字型 profiles。一個正在寫入的 snapshot 加上一份最新待寫 snapshot，後續變更合併，不建立無界佇列；與互動式 picker 使用不同檔案工作，但由同一 Files owner 保留、撤銷新工作並在關窗時 drain／join。寫入失敗可見且不假裝保存完成，沒有自動重送舊 snapshot。

一般保存先驗證原檔，原樣備份後同目錄原子替換；損壞、未知版本、重複／無效名稱、超量均保留原檔，本次到訪只留記憶體，直到明確清除。清除先以空清單原子替換 `.bak`，再替換主檔，不能把待清除紀錄複製進備份；任一步失敗都回報未完整清除。清除意圖不會被後來合併的到訪覆蓋，失敗後也保留至下一次明確變更；兩檔並非單一跨檔交易，故不宣稱失敗時兩者完全不變。

## 測試與邊界

自製 board-switch fixture 沒有站端 session 記錄；navigation suite 的獨立 expected 核對板名、空列表、固定提示、正式名稱欄位、主選單／閱讀多步、列表選中後進入與直接到達、假提示、同步分片、相同 revision 不重送及可控制時鐘期限。

production Connection 的 loopback 逐筆比對完整步驟，檢查同步中不送板名但 Ping／Pong 正常、工作期間保活暫停、重複與過期請求、取消所有權、原始輸入介入、晚到提示、逾時、重連不重播及工作中正常關閉。一般測試不連 PTT。平台、原生 IME、實站格式與部署各自驗收，合成到達不表示實站操作已通過。
